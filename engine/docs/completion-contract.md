# Completion contract v1

The inspected 150-scene run committed its opening six scenes, then paused before packet 2. Its required context estimate was 65,633 tokens against a 44,290-token context allowance. The predecessor's entire metadata delta appeared again as current constraints and source evidence. The opening also authored no navigation edges, and its only ending prerequisite was marked `intentionally_unresolved` even though the update described ongoing work.

This revision applies to new CLI runs. Capability preflight freezes `completion_contract_version: 1` in the execution policy. Protocol additions are optional for legacy policies; existing snapshots, manifests, committed writing and paused runs are not migrated.

## Context and budgets

Scoped predecessor contracts contain source identity, constraint IDs, reading-link interfaces and state exports. They do not copy the entire constraint delta. A dependency alone no longer promotes every predecessor fact to mandatory context. Explicit binding obligations and their prerequisite/evidence closure remain mandatory, as do relevant continuity and explicit negative-knowledge constraints for involved subjects. Other history and soft pressure compete for optional space without being deleted from the index.

`SHARED CONTEXT VALUES` factors exact repeated JSON objects and strings across the predecessor, current-state and evidence roles. `$context_ref` expansion recovers the complete included values; similarity, summaries and inferred equivalence do not substitute for evidence. Existing commit/hash/pointer checks still protect original source units. Receipts record shared-value savings, mandatory inclusion reasons, normal versus hard limits, and the largest units on a genuine capacity failure.

New runs freeze `normal_prepared_context_tokens: 49152`. Their hard input allowance uses the smaller frozen/actually loaded model window after reserving the requested output and safety space. Optional material stays within the normal target and available correction headroom; only mandatory context uses the additional loaded capacity. Envelope estimates include messages, response schemas and other request fields. Corrections and expanded-output retries receive their own checks before sending. No evidence is clipped to fit.

## Navigation and prerequisite readiness

Each new packet-plan annotation includes `required_navigation`: a map from every local scene technical slot to its intended destination slots. Ending plans use an empty map. The schema closes destinations over all allocated scene and ending slots. Combined validation requires every surface to be reachable from the opening and every scene to have a route to an ending. Loops and reconvergence remain legal. If needed, a focused model request repairs only these routing fields while all Architecture records are still uncommitted.

The scene author supplies labels and transitions for the planned exits. Missing or reserved-only exits fail before artistic preservation. A deterministic route through the authored contract is checked progressively against actual committed/candidate state conditions and effects, and checked again at completion. This verifies a completion route, not every possible conditional reading path. The engine adds no Next/Previous reading fallback and does not rewrite committed choices.

Soft assignments remain advisory. Long-range hard assignments are pressure before their deadline rather than demands for a terminal update in the opening; they become binding by the final remaining literary plan. Eligible earlier satisfaction is still allowed when supported. This matters because the historical `obligations_advanced` field records terminal metadata updates rather than ordinary dramatic progress.

Ending prerequisites offer only supported satisfaction. Proposed resolutions receive a focused source audit with exact quotations checked against the unchanged scene/artifacts. Ongoing or unsupported updates are removed from uncommitted metadata, leaving the obligation active. The engine never coerces an ambiguous status to satisfaction or reopens committed canon. Scheduling and candidate validation identify prerequisites that have no remaining literary opportunity before attempting ending generation.

## Publication and verification

The dependency-free baseline exports exact Markdown sources as well as reader pages and work data. Final validation checks page/asset presence, internal links, rendered prose and byte-identical source exports. Missing pages or invalid rendered output prevent publication. Source-byte checks preserve CRLF and Unicode rather than normalizing them during verification.

Regression definitions cover the saved packet-2 density, dense 150-scene history, exact expansion, loaded headroom and full-envelope limits, navigation planning/conditions, long-range deadlines, supported resolutions, and complete 150-scene static publication. Engine cleanup verification now includes network-blocked synthetic tests, a current scaffold generation through static publication, interruption/resume, and immutable-source checks. Live-model behavior remains for the operator’s fresh run.
